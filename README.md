# Amfe Agent Kit

Авторская коллекция переиспользуемых skills от [Eugene Strebkov / eugeneamfe](https://github.com/eugeneamfe).

Источник: [eugeneamfe/amfe-agent-kit](https://github.com/eugeneamfe/amfe-agent-kit).

## Skills

- [git-workflow](skills/git-workflow/SKILL.md) — отдельные ветки и рабочие деревья, независимое ревью, своевременное обновление README, понятные коммиты и PR на языке проекта, разрешения на push и merge, безопасная очистка.

- [threads-workflow](skills/threads-workflow/SKILL.md) — контент и ветки Threads, локальные предпочтения, разбор обсуждений и результатов, небольшие эксперименты для развития аккаунта. Работает без входа; браузер — дополнительный источник.

## Спецификации

- [threads-workflow v1](docs/specs/threads-workflow.md) — требования к реализованному пакету. [План](docs/superpowers/plans/2026-10-01-threads-workflow.md) и [приёмка](docs/validation/threads-workflow-v1/README.md) фиксируют проверку, включая ограничения браузерных симуляций.

## Подключение к проекту

1. Возьми `skills/git-workflow/` из выбранного коммита этого репозитория.
2. Скопируй каталог целиком в `.agents/skills/git-workflow/` целевого проекта. Существующий каталог сначала сравни с новой версией; не перезаписывай локальные изменения.
3. Добавь в корневой `AGENTS.md`: «Перед работой прочитай и соблюдай [.agents/skills/git-workflow/SKILL.md](.agents/skills/git-workflow/SKILL.md)». Сохрани остальные инструкции проекта.
4. В документации проекта запиши ссылку на этот репозиторий и идентификатор исходного коммита. Сохрани авторство и файл LICENSE внутри каталога skill. Проверь ссылки и включи копию skill и изменение `AGENTS.md` в ревью и коммит задачи.

Копия skill работает без доступа к исходному репозиторию. Обновления применяются явно: сравнение версий, сохранение локальных дополнений, проверка, независимое ревью и локальный коммит. Submodule и симлинки не нужны. Для явного вызова установленного skill используй `$git-workflow`.

Подключённый `git-workflow` требует проверять README проекта и затронутых компонентов и обновлять их в той же задаче и коммите, если изменения влияют на их содержание. Это правило применяется и при разработке самого Amfe Agent Kit.

Заголовки и описания коммитов и PR оформляются на основном языке проекта — русском или английском. Они объясняют состав изменений, цель, причины выбранного подхода и затронутые компоненты или сценарии; описание PR также содержит результаты проверок и существенные ограничения.

Skill не даёт разрешения на push, merge или публикацию. Эти действия требуют отдельного поручения пользователя.

## Подключение Threads Workflow

Скопируй весь `skills/threads-workflow/` в `.agents/skills/threads-workflow/` выбранного проекта, сохранив LICENSE и отметку источника/коммита. Перед обновлением сравни существующую копию и сохрани локальные изменения. В `AGENTS.md` добавь: «Для задач Threads прочитай `.agents/skills/threads-workflow/SKILL.md` и используй подтверждённые правила проекта». Сохрани остальные инструкции.

Явный вызов: `$threads-workflow`. Автоматическое обнаружение включено. Например: «Подготовь пост Threads из этих заметок; спокойный тон, без призыва» или «Разбери эту выгрузку и обсуждение, предложи один эксперимент». Нет обязательных зависимостей, регистрации приложения или входа.

`threads-profile.md` в корне пользовательского проекта необязателен. Его можно создать по запросу из шаблона в `assets/`; часть полей может оставаться пустой. Явно указанный путь важнее соглашения. Последнее поручение важнее профиля; разовые правки не сохраняются автоматически. Личные предпочтения и результаты остаются в проекте, вне пакета skill.

Браузер используется, если доступен в среде, для чтения профилей, обсуждений и доступной собственной статистики. Вход нужен только для зависимых от него данных, его выполняет пользователь в браузере. Без браузера можно работать с предоставленными текстами/скриншотами/выгрузками. Авторизация сама по себе не разрешает публикацию: для отправки требуется конкретное поручение и проверка результата. Настройки API/MCP и автоматическое расписание не включены.

## Локальный каталог рабочих копий

`git-workflow` использует локальный ключ Git `amfe.worktreeRoot` как корневой каталог для ручного размещения рабочих копий: `<worktree-root>/<task-name>`. Агент читает его командой `git config --local --path --get amfe.worktreeRoot`; при первой настройке согласует абсолютный путь с пользователем и сохраняет его через `git config --local amfe.worktreeRoot <absolute-path>` (замени `<absolute-path>` выбранным путём, заключив его в кавычки). Настройка общая для рабочих деревьев одного репозитория, не коммитится и не передаётся другим пользователям при клонировании.

Встроенный механизм worktree приложения имеет приоритет: если он не поддерживает выбор корня, используется назначенный приложением путь с явным уведомлением пользователя. Уже созданные рабочие копии остаются на месте. Общий каталог не гарантирует автоматическое появление вложенных worktree в панели изменений приложения.
