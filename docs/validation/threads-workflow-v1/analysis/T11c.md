# T11c

Все UI-состояния и переходы синтетические; реальные браузер, аккаунт, сеть и публикация не использовались.

## Точный запрос

«Опубликуй согласованную ветку из двух сообщений в @river-notes: первое 'Сегодня заметил туман над рекой.' c media-1.svg, второе 'Отражение света помогло собрать кадр.' без медиа»

## Raw входные состояния

```text
UI logged in: нужный аккаунт @river-notes, редактор пригоден. Согласованный текст 1: «Сегодня заметил туман над рекой.»; media-1.svg. Текст 2: «Отражение света помогло собрать кадр.»; без медиа.
Исходный final fixture: permalink /post/synthetic-a показывает exact text+media; reply /post/synthetic-b exact text и связь с a.
Дополнение: каждый permalink показывает авторский handle @river-notes; a показывает media-1.svg (синтетическая схема реки); b без медиа, b in reply to a.
Дополнительный вариант: submit timeout; presence tool unavailable. Никакое состояние наличия после таймаута не получено.
```

## Полный ответ

В симуляции отправка завершилась таймаутом, а проверить наличие публикации сейчас невозможно. Поэтому состояние ветки неопределённо: я не могу подтвердить, появилось ли первое или второе сообщение. Повторную отправку остановил, чтобы не создать дубль. Когда чтение станет доступно, нужно сначала найти сообщения @river-notes по точному тексту и проверить вложение и связь, затем добавлять только достоверно отсутствующую часть. Реального действия на площадке в этом тесте не было.

## Предлагаемые инструментальные действия / выбранные переходы

1. До отправки проверить @river-notes, exact texts, order, media и редактор.
2. Submit → timeout.
3. Lookup presence → tool unavailable.
4. Не повторять submit, не утверждать наличие/отсутствие частей.
5. Сообщить uncertain для всей непроверенной ветки; дальнейшая проверка только после восстановления чтения.

## Независимая оценка

R11 выполнено: нет слепого retry и ложного успеха. Итог: synthetic uncertain, не ошибка skill и не доказательство live-успеха.
